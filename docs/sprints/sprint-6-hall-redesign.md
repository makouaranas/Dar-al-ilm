# Sprint 6 — Premium Hall: Architecture, Signage, Bookcases and Baked Light

**Sprint goal:** bring the hall approved in the Blender look development (`tools/lookdev/hall.py`)
into the app, so the hall people walk through looks like the renders: a real arcade with fluted
columns, a clerestory and skylight wells with mashrabiya lattices, a three-level signage system,
crafted bookcases with exactly placed books, and soft light baked offline.

**Read first:** `AGENTS.md`, `docs/DESIGN.md` §1–5 (concept, hall, lighting, materials, books),
`tools/lookdev/README.md` and `tools/lookdev/hall.py` (the reference scene), then
`docs/ARCHITECTURE.md` §9 (layout), §10 (3D performance rules) and §14.3 (end-to-end tests).

**Rules for this sprint**
- The look-development scene is the visual reference, not a file the app loads. The app keeps
  building the hall procedurally from the library (any number of categories and books); Blender
  is used offline only, for reference renders and for baking light maps (US-22).
- The rules of `AGENTS.md` §1 still hold: `frameloop="demand"`, zero frames when idle, no looping
  idle animation, canvas text for every sign, no network assets, one camera owner.
- Budgets (`docs/ARCHITECTURE.md` §10.4) are checked in every story's e2e through
  `renderer.info`, with a 24-category, 600-book library, at the story's evidence poses:
  < 150 draw calls and < 300 k triangles in view, architecture textures ≤ 64 MB.
- Layout values marked *(tunable)* may change; every change is written back to
  `docs/ARCHITECTURE.md` §9 in the same commit. Design changes are written to `docs/DESIGN.md`
  and recorded as decisions in `docs/REQUIREMENTS.md` §15.
- The real-time hall cannot reach the global illumination of a Cycles render. The target is the
  same architecture, materials, signage and light direction, with the soft light baked in;
  differences that remain are listed in each story report.
- FPS cannot be measured in the cloud container (software WebGL). Each story's browser check
  asks the user to read the F2 debug overlay on their own machine.

## US-19 — Hall Architecture: Arcade, Clerestory, Skylight Wells and Lattice Windows

**Use case:** UC-03 (browsing by walking).

**Files (scope):**
- `frontend/src/components/3d/HallRoom.tsx`, `frontend/src/components/3d/CategoryColumn.tsx`
  (the columns move; the existing blade plaque hangs from the arcade beam until US-20)
- `frontend/src/lib/hallLayout.ts` (+ test), `frontend/src/lib/flightPath.ts` (+ test)
- `scripts/generate_textures.py`, `frontend/public/textures/` (+ `LICENSES.md`)
- `frontend/e2e/us-19.spec.ts` (new); `frontend/e2e/us-09.spec.ts`, `frontend/e2e/us-12.spec.ts`
  (poses and lanes that move with the columns)
- `docs/ARCHITECTURE.md` §9.4, §10.4, §10.6; `docs/DESIGN.md` §1–2, §4;
  `docs/REQUIREMENTS.md` §15; `PROGRESS.md`

**Acceptance criteria:**
- **Arcade:** a limestone beam runs along both nave edges at the side-aisle ceiling height.
  Fluted limestone columns (base, plinth, three-step capital) stand under it at every bay
  boundary and twice in the entrance zone, never inside a bay opening. Beam, columns,
  partitions and walls meet without gaps, slits or coplanar flicker.
- **Clerestory:** the plaster wall above the arcade carries a mashrabiya lattice window over
  each bay (alpha-tested dark-wood lattice in front of a bright sky).
- **Nave ceiling:** every skylight sits in a 0.8 m deep well framed by plaster beams, with a
  lattice at its mouth; the floor light map stays aligned under the skylights.
- **Side aisles:** slatted ash ceilings; an arched lattice window on each bay's back wall;
  arched windows with a built-in window seat in the entrance zone; limestone skirting.
- **Entrance and end wall:** the pointed entrance arch opens onto a bright forecourt; the
  end-wall niche keeps its bench and warm wash.
- **Materials:** limestone floor tiles with subtle large-scale variation and brass inlay lines,
  matte plaster, ash and walnut with visible grain at reading distance (1K textures generated by
  `scripts/generate_textures.py` and committed; nothing downloaded).
- **Layout:** columns move from the bay centres (`|x| = 2.2`) to the bay boundaries on the
  arcade line; search flights enter a bay on its centre line, and every flight still keeps at
  least 9 cm from every collider (unit-tested over the demo library and a 630-book library).
  Walking collides with the new columns and window seats.
- **Budgets** as in the sprint rules; zero frames while idle.

**Verification command:**
```bash
cd frontend && npm run typecheck && npm run test:unit && npm run build && npm run test:e2e -- us-19 us-09 us-12
```

**Visual evidence:** `us-19/entrance.png`, `us-19/nave.png`, `us-19/bay-opening.png`,
`us-19/ceiling.png`, `us-19/entrance-ar.png`. Claude compares them with the look-development
shots (entrance, nave) and lists the differences.

**Browser check (physical machine):** walk from the entrance to the end wall: columns stand at
the bay boundaries, the openings are clear, the ceiling shows the skylight wells and lattices,
nothing flickers or leaves a slit of light. Press F2 while walking: FPS and draw calls.

## US-20 — Signage in Three Levels: Section Headers, Range Plates and Directory

**Use case:** UC-03 (finding a category), UC-01 (categories are named by the user).

**Files (scope):**
- `frontend/src/components/3d/Signage.tsx` (new), `frontend/src/components/3d/CategoryColumn.tsx`
  (blade plaque removed), `frontend/src/components/3d/HallRoom.tsx` (compose)
- `frontend/src/lib/canvasText.ts` (+ test) (sign layouts), `frontend/src/lib/i18n.ts`
  (directory and count strings)
- `frontend/src/components/3d/PlayerControls.tsx`, `frontend/src/lib/flightPath.ts` (+ test)
  (flight to a bay from the directory)
- `frontend/e2e/us-20.spec.ts` (new); `frontend/e2e/us-10.spec.ts` (plaque tests move to the
  headers)
- `docs/ARCHITECTURE.md` §9.4, §10.7; `docs/DESIGN.md` §1 (principle 2), §2, §8;
  `docs/REQUIREMENTS.md` §15; `PROGRESS.md`

**Acceptance criteria:**
- **Level 1, section header:** each bay's category name in dark bronze cut letters on the
  plaster band above the arcade beam over its opening, grazed by a warm line of light from a
  slim brass trough on the beam (baked or emissive; no real-time light per sign). Readable from
  the bay opening and from 10 m down the nave.
- **Level 2, range plate:** a brass plate at eye level (centre about 1.5 m) on the end panel of
  every bookcase that faces the nave, with the category name and its book count, using the
  Arabic plural forms of `docs/DESIGN.md` §12.2 ("كتابان", "11 كتابًا").
- **Level 3, directory:** a slim limestone stele beside the entrance path with an engraved
  brass panel listing every category in bay order, each with an arrow toward its side of the
  nave; with many categories the list flows into two columns, then ends with "and {n} more".
  The directory is a shortcut: hovering a line highlights it (gilt) with a pointer cursor, and
  clicking it flies the camera to that bay's opening, facing into the bay, along the same
  cleared path and timing as a search flight (300 ms fade cut with reduced motion). Search
  stays the keyboard path to a category.
- **Hierarchy and consistency:** header letters at least three times the plate text height;
  one sign grid (margins, rules, brass, typography) shared by all three levels. Category names
  appear as the user typed them (no forced case); Latin in Inter SemiBold, Arabic in Cairo Bold,
  right to left with joined letters and no letter spacing; long names shrink to fit (min 60 %),
  then end with an ellipsis.
- Every sign is drawn on a 2D canvas after `document.fonts.load()` resolves, uploaded as a
  single-channel mask (the brass colour comes from the material). Renaming a category redraws
  its header, plates and the directory and disposes the old textures; adding, moving or deleting
  a book redraws only that category's plates.
- **Budgets** as in the sprint rules; signs add at most 2 draw calls per bay.

**Verification command:**
```bash
cd frontend && npm run typecheck && npm run test:unit && npm run build && npm run test:e2e -- us-20 us-10
```

**Visual evidence:** `us-20/header-programming.png`, `us-20/header-arabic.png`,
`us-20/plate.png`, `us-20/plate-ar.png`, `us-20/directory.png`, `us-20/directory-ar.png`,
`us-20/nave-signs.png`. Claude checks that Arabic letters are joined and correctly ordered.

**Browser check (physical machine):** from the entrance, read the directory and find a
category; walk down the nave and read each header; add a book and see the plate's count change;
rename a category in Settings and see all three signs change; click a directory line: the
camera flies to that bay.

## US-21 — Crafted Bookcases and Exact Book Placement

**Use case:** UC-03 (browsing the shelves), FR-05.

**Files (scope):**
- `frontend/src/components/3d/Bookcase.tsx`, `frontend/src/components/3d/BookSpine.tsx`,
  `frontend/src/components/3d/HallRoom.tsx` (bookends)
- `frontend/src/lib/hallLayout.ts` (+ test) (book placement)
- `frontend/src/lib/shelfCheck.ts` (+ test) (new: the collision check)
- `frontend/e2e/us-21.spec.ts` (new); `frontend/e2e/us-11.spec.ts` (shelf evidence poses)
- `docs/ARCHITECTURE.md` §9.3; `docs/DESIGN.md` §2, §5; `docs/REQUIREMENTS.md` §15;
  `PROGRESS.md`

**Acceptance criteria:**
- **Carcass:** light ash bookcases with a plinth, a cornice, a back panel, walnut shelf lips and
  brass bookends; the end panel facing the nave carries the range plate (US-20) with a
  mashrabiya insert below it.
- **Books on the shelf:** each book's bottom rests exactly on its board, with 2 mm gaps between
  neighbours, spines aligned 1 cm behind the shelf lip, clear of the side panels and of the board
  above. Real books keep their shelf and slot order (FR-05, `docs/ARCHITECTURE.md` §9.1); no
  invented books are added.
- **Collision check:** `shelfCheck.ts` (a port of `hall.py --check`, oriented-box separating-axis
  tests) runs over the demo library and generated libraries with the extreme book sizes of
  `docs/ARCHITECTURE.md` §9.2 and full 30-book shelves, and reports zero book–book overlaps,
  zero books cutting into a board or panel and zero unsupported books. A test injects faults
  (a book moved into its neighbour, one sunk into the board, one floating) and expects each to be
  reported.
- **Row ends:** after the last book, a brass bookend; the rest of the shelf stays empty (no
  decorative objects, decision of 2026-10-22).
- Hover, present, search flights and the hall ↔ reader transition still find every book at its
  new position (us-11 and us-12 suites pass).
- **Budgets** as in the sprint rules; still one instanced draw call for the books of a bookcase.

**Verification command:**
```bash
cd frontend && npm run typecheck && npm run test:unit && npm run build && npm run test:e2e -- us-21 us-11 us-12
```

**Visual evidence:** `us-21/shelf-full.png`, `us-21/shelf-partial.png`,
`us-21/shelf-mixed-sizes.png`, `us-21/bookcase-end.png`, `us-21/empty-category.png`. Claude

## US-22 — Baked Light, Bay Reading Nooks and Look-Development Review

**Use case:** UC-03 (browsing), UC-04 (reading in the hall).

**Files (scope):**
- `tools/lookdev/bake.py` (new: Blender light-map bake of the hall's modules),
  `tools/lookdev/README.md`
- `frontend/public/textures/baked/` (new light maps, + `LICENSES.md`)
- `frontend/src/components/3d/HallRoom.tsx`, `frontend/src/components/3d/ReadingNook.tsx` (new)
- `frontend/src/lib/hallLayout.ts` (+ test) (the nook zone and its collider)
- `frontend/e2e/us-22.spec.ts` (new)
- `docs/ARCHITECTURE.md` §9.4, §10.4, §10.6; `docs/DESIGN.md` §2–3; `docs/REQUIREMENTS.md` §15;
  `PROGRESS.md`

**Acceptance criteria:**
- **Baked light:** soft indirect light and contact shading for the hall's repeating modules
  (entrance zone, nave segment, bay segment, bay end, column, bookcase carcass) are baked offline
  in Blender (Cycles) into light maps on a second UV channel, committed as WebP within the 64 MB
  architecture texture budget. The app combines them with its existing key light and single
  shadow; nothing runs Blender at app time, and the hall still renders zero frames when idle.
- **Reading nooks:** each bay ends in a reading nook under its window: a walnut table, two
  chairs and a brass reading lamp (emissive shade and halo), with a warm pendant at the bay
  opening. The nook adds about 1.6 m at the back of every bay (the bay depth formula and the
  hall width in `docs/ARCHITECTURE.md` §9.4 grow by it). The nook is a collider; walking and
  flights avoid it.
- **Look-development review:** app screenshots at four poses matching the look-development
  shots (entrance, nave, bay, desk) are placed side by side with fresh Blender renders and sent
  to the user; the report lists every visible difference that remains.
- **Budgets** as in the sprint rules; GPU texture memory with the reader open stays < 400 MB.

**Verification command:**
```bash
cd frontend && npm run typecheck && npm run test:unit && npm run build && npm run test:e2e -- us-22 us-09 us-11 us-12
```

**Visual evidence:** `us-22/compare-entrance.png`, `us-22/compare-nave.png`,
`us-22/compare-bay.png`, `us-22/compare-desk.png` (app left, Blender right), `us-22/nook.png`.

**Browser check (physical machine):** walk the whole hall with F2 open: soft light in the bays
and under the arcade, warm pools at the nooks, FPS steady while walking; compare with the
look-development pictures.

## Decisions taken with the user (2026-10-22)

1. **Empty shelf space stays empty.** The look-development scene filled every shelf with
   invented books; the app shows only the user's real books, followed by a brass bookend, and
   the rest of the shelf stays bare wood.
2. **Reading nooks:** yes. Each bay ends in a reading nook, about 1.6 m deeper (US-22).
3. **The directory is clickable:** clicking a line flies to that bay (US-20).
